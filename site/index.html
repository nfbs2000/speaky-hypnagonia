01 / THE GAME

전투 용어를 바꾸면
플레이의 의미가 바뀐다

Hypnagonia는 Slay the Spire 계열의 덱 구성·드로우·비용·상태 효과를 사용하지만, 전투의 언어를 심리적 은유로 다시 씁니다. 플레이어는 Dreamer이며, 적은 현실의 불안과 문제에서 나온 Torment입니다. 공격 수치는 Interpretation, 적의 체력은 Comprehension, 받는 피해는 Stress, 생존 한계는 Anxiety가 됩니다.

핵심은 테마를 카드 위에 덧씌운 것이 아니라, 승리와 패배를 설명하는 기본 명사를 교체한 데 있습니다.

PLAYER VOCABULARY

한 턴을 구성하는 여섯 개념

01

Interpretation

Torment를 이해하는 진행량입니다. Comprehension 한계에 도달하면 Torment를 극복합니다.

02

Comprehension

Torment가 요구하는 해석의 총량입니다. 일반 덱빌더의 적 체력에 해당합니다.

03

Stress

Torment의 intent가 가하는 압력입니다. Confidence를 먼저 깎고 남은 값이 Anxiety를 올립니다.

04

Anxiety

Dreamer의 실패 한계입니다. 최대치에 도달하면 악몽에서 깨어나 run이 끝납니다.

05

Immersion

대부분의 카드를 사용할 때 지불하는 턴 자원입니다.

06

Confidence / Perplexity

각각 Dreamer와 Torment의 방어층입니다. Stress와 Interpretation이 본체에 닿기 전에 흡수합니다.

근거: CardConfig.gd의 EXPLANATIONS

02 / RUN LOOP

악몽은 세 Act의
선택과 전투로 진행된다

  1. 01
    Dreamer 구성

    Archetype과 시작 카드, 성격 요소를 선택합니다.

  2. 02
    Journal 선택

    현재 Pathos와 확률에 따라 1~3개의 다음 encounter가 제시됩니다.

  3. 03
    Ordeal 또는 사건

    Torment 전투, 위험·비전투 사건, 상점, 휴식이 run을 변화시킵니다.

  4. 04
    보상과 덱 변화

    새 카드, Memory, Artifact와 영구적인 카드 향상·흉터가 누적됩니다.

  5. 05
    다음 밤의 층

    Early Night, Deep Sleep, Pre-Dawn을 거쳐 Act 보스와 마주합니다.

코드의 소유자

SingleRun이 Act, 남은 encounter, 보스와 journal 선택을 관리하고, GameSave가 RNG seed·player·encounter·difficulty를 함께 저장합니다.

04 / CARD ENGINE

카드 텍스트와 실행 규칙을
별도로 정의한다

카드 한 장은 표시용 definition과 실행용 script로 나뉩니다. Definition은 이름·Type·Cost·Abilities·수치·업그레이드를 담고, script는 어떤 task를 어떤 subject에게 실행할지 기술합니다.

범용 ScriptingEngine은 task를 queue로 만들고 비용 dry-run을 먼저 수행합니다. 실제 상태 변경은 modify_damage, assign_defence, apply_effect 같은 executor 경계가 담당합니다.

DEFINITION무엇을 보여 줄 것인가
"Interpretation": {
  "Type": "Action",
  "Abilities": "{damage} for {damage_amount}",
  "Cost": 1,
  "_amounts": { "damage_amount": 6 }
}
SCRIPT무엇을 실행할 것인가
{
  "name": "modify_damage",
  "subject": "target",
  "needs_subject": true,
  "amount": {
    "lookup_property": "_amounts",
    "value_key": "damage_amount"
  }
}
Card definition→ State script→ ScriptTask queue→ Dry-run→ Executor→ Board state

근거: SetDefinition_Core.gd · SetScripts_Core.gd · ScriptingEngine.gd

05 / TURN & PREDICTION

턴은 signal로 흐르고, intent는 dry-run으로 예측된다

Player turn

시작 signal을 보내고 카드를 사용합니다. 턴 종료 시 손을 정리하고 다음 손을 준비합니다.

Enemy turn

Board가 살아 있는 Torment를 순서대로 activate하며 각 완료 signal을 기다립니다.

Intent prediction

상태 snapshot과 cost dry-run으로 예상 Stress·방어 변화를 계산해 intent icon에 표시합니다.

예측은 실제 실행과 다르다

source에는 예측값을 갱신하는 별도 cache와 snapshot이 있습니다. 화면에 보이는 intent는 다음 행동을 돕는 계산 결과이지, 이미 발생한 전투 기록이 아닙니다.

08 / AI-GENERATED CONTENT

AI는 플레이어가 아니라
이야기 공급 경로에 있다

README가 말하는 AI 결합은 카드 선택을 실시간으로 대신하는 agent가 아닙니다. 소스의 KoboldAI는 story generation 경로를 제공하고, AIStories와 AIRatings는 평가 중이거나 확정된 이야기를 원격 서비스에서 가져와 encounter에 연결하고 사용자의 평가를 제출합니다.

카드 규칙, turn, 대상 선택, 결과 계산은 여전히 Godot의 deterministic rule engine이 소유합니다. 원격 story endpoint의 현재 가용성은 이 가이드에서 성공으로 가정하지 않습니다.

KoboldAIstory generation → AIStoriesevaluating / finalized selection → EncounterStoryjournal presentation

근거: KoboldAI.gd · AIStories.gd · AIRatings.gd

09 / TRUTH BOUNDARY

이 소스로 확인되는 것과
별도로 검증해야 하는 것

소스에서 확인됨

  • Godot 3.6 export와 Card Game Framework 기반 구조
  • Definition → ScriptTask → Executor의 카드 실행 경계
  • 세 Act와 journal 기반 encounter 선택
  • RNG seed를 포함한 run 저장·복원 계약
  • AI story 조회·평가 코드와 gameplay 규칙의 분리

페이지가 보장하지 않음

  • 현재 모든 카드와 encounter의 밸런스 또는 무결성
  • 과거 AI story endpoint가 지금도 작동한다는 주장
  • 스크린샷이 최신 build의 모든 UI를 대표한다는 주장
  • AI 생성 이미지·shader별 라이선스가 하나로 동일하다는 주장
  • 이 공개 포크가 upstream의 공식 배포라는 주장
